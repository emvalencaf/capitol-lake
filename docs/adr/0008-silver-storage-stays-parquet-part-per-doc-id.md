# Silver stays Parquet on S3, one `part-<doc_id>.parquet` per filing, no compaction

Lifting to AWS could have moved the silver layer from the Hive-partitioned Parquet layout decided locally in #6 (`silver/<table>/chamber=.../year=.../part-*.parquet`) to Iceberg, for schema evolution and time travel. Iceberg only pays off with a catalog, but #6 already deferred any catalog to the Phase 4 fog, and #4 found the LocalStack Hobby tier has no free Glue/Athena to develop and test against — so adopting Iceberg now would mean designing against real AWS with no local parity, for a benefit this map's Destination doesn't require yet.

Decided: silver keeps the same Parquet layout unchanged on S3. Each Lambda invocation (one per filing, per #18) writes its own part file named `part-<doc_id>.parquet` rather than a random or timestamped name, mirroring the hash-gated idempotency contract #9 gave the bronze layer — reprocessing a filing overwrites its own file instead of duplicating rows in the partition. No compaction job is introduced: at current volume (~451-515 House PTRs/year, per #3) many small part files per partition is an accepted cost, not a problem to solve in this phase. Iceberg, and any catalog decision it would require, stays in the Phase 4 fog alongside Gold and Athena.
