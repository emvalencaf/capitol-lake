# Every collector enqueues its own extract SQS message; the bronze-bucket S3-event bridge is gone

ADR-0015 fixed Senate's bronze-to-extract chain by having the bronze bucket's S3 event notification target extract's own SQS queue instead of invoking extract's Lambda directly, so a Senate-triggered failure got the same retry/DLQ handling House's `house_collect`-built `extract_queue_message` already had. That worked, but it kept an asymmetry: House's handler always knew and sent its own `{"bronze_key": ...}` message, while Senate's two collectors (`senate_collect`, `senate_collect_automated`) relied on infra to notice a bronze write after the fact and re-wrap it as a forwarded S3 notification — a second message shape `shared.orchestration.bronze_key_records_from_event` had to unpack, and a mechanism invisible from the handler's own code (you couldn't tell whether a collector chained into `extract` by reading its handler).

Decided: `senate_collect` and `senate_collect_automated` now build and send their own `extract_queue_message` per bronze key they actually wrote, exactly like `house_collect` — the same `_enqueue_written_filings` pattern, guarded the same way by an optional `EXTRACT_QUEUE_URL` env var (unset keeps a handler runnable standalone, e.g. against MinIO with no queue configured). Each collector's IAM role gets its own `sqs:SendMessage` policy scoped to extract's queue ARN (mirroring `house_collect_sqs`), rather than the bucket-and-queue policy dance ADR-0015 needed to let `s3.amazonaws.com` deliver into the queue.

This removes `infra/modules/scheduling`'s `aws_s3_bucket_notification`/`aws_sqs_queue_policy`/`data.aws_iam_policy_document.allow_s3_send_to_extract_queue` entirely, along with the variables that only existed to wire the bronze bucket and extract's queue into that module (`bucket_id`, `bucket_arn`, `extract_queue_arn`, `extract_queue_url`, `senate_bronze_prefix`, `senate_bronze_suffix`). `shared/orchestration.py`'s `_bronze_key_records_from_sqs` no longer unwraps a nested `{"Records": [...]}` S3-notification body — an SQS record's body is always `{"bronze_key": ...}` now, from any of the three collectors.

Trade-off accepted: a bronze object written any other way (a human uploading straight to S3, bypassing every collector) no longer chains into `extract` automatically — ADR-0015's bridge covered that case "for free"; this doesn't. Nothing in this repo does that today (every write goes through one of the three collector handlers), and `bronze_key_records_from_event`'s plain `{"bronze_key": ...}` invocation shape still lets anyone kick off `extract` by hand for a manually-uploaded object.
