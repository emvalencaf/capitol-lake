# `collect_house` skips a known `doc_id` entirely, rather than re-fetching it to hash-compare

`collect_house` (`src/shared/bronze_write.py`'s hash-gated writer) used to fetch every filing's PDF on every run, including a `doc_id` already stored in bronze, purely to compute its sha256 and compare against the recorded one — a defensive design (`35dca40`, `feat(stages/bronze-write)`) meant to never silently lose a same-`doc_id` content correction. In practice this meant a daily scheduled run re-downloaded an entire year's backlog (~500 filings) every single day, rate-limited at ~1 request/second, purely to confirm nothing had changed for filings collected long ago.

`docs/research/house-ptr-amendment-doc-id-behavior.md` checked that assumption against the House Clerk's own primary sources (the PTR form's Initial-Report/Amendment field and instructions, the Committee on Ethics' Instruction Guide, and a full year's live annual index): a correction is filed, published, and indexed as a **distinct, new `DocID`**, not an edit replacing the original's content under the same `DocID`. Confidence is high, but not absolute — no primary source makes a flat "a `DocID` is never reused" guarantee, and the research didn't find a live example of an amended PTR specifically (only an amended annual FD).

Decided: `collect_house` now checks `read_existing_sha256(meta_key)` **before** fetching a filing's bytes. A `doc_id` already on record is treated as immutable — skipped with no HTTP fetch, no `rate_limiter.wait()` charged against it, and no re-hash — and reported as `"skip"` (in `on_progress`) / collected under a new `skipped` key in `collect_house`'s return dict (renamed from `noop`, since there is no hash comparison happening to call a no-op). Only a `doc_id` never seen before gets fetched and written. `house_collect/handler.py`'s wide-event field became `skipped_count` to match.

Trade-off accepted: if the House Clerk ever does silently replace a `DocID`'s content, this collector will keep serving the stale bronze copy indefinitely, with no automatic way to notice — the research's residual gap becomes a live risk instead of a hypothetical one. This is judged acceptable given the research's confidence level and the very large, recurring cost (network time, House Clerk site load) of re-fetching every known filing every day. If evidence ever surfaces of a same-`DocID` correction, `existing_sha256`-gated hash comparison can be reinstated for House specifically without touching any other stage.

This change is scoped to House only. Senate's collectors (`senate_collect`, `senate_collect_automated`) still hash-compare on every run — the repo's own code comment (`shared/senate_index.py`) assumes a Senate eFD amendment gets its own separate UUID, but that assumption has not been checked against a primary Senate source (noted, not resolved, in the same research file).
