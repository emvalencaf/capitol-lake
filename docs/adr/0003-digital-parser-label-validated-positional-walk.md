# Digital parser validates labels before accepting positional field values

pypdf renders bold section/row labels (`Filer Information`, `Transactions`, `Filing Status:`, `Sub Owner`) with unpredictable internal whitespace from bold-font glyph-width heuristics, so literal label matching fails. Issue #7's notebook confirmed this garbling is systematic across all sampled digital filings, not character-level OCR noise, and that even a "shape-only" parser (anchoring purely on the `date date $range` transaction-line regex) still needs to walk backward/forward from that anchor to read adjacent field values like asset name, Filing Status, and Sub Owner.

Decided: the digital parser drops section headers as anchors entirely (nothing depends on them). For row-level fields, it strips all whitespace from each candidate line (`re.sub(r"\s+", "", s)`) and matches it exactly against a small fixed label dictionary before accepting the adjacent value — rather than reading a fixed line offset positionally with no text check. A pure positional walk was rejected: when an optional line (e.g. Sub Owner) is absent for a given transaction, a fixed offset would silently misattribute the wrong line's text to that field, whereas label validation turns a missing line into a clean null. This keeps the same honest-null precedent as ADR 0002: on no label match, the field is null with low confidence rather than guessed.

Addendum (#36): with pypdf 6 the garbling changed shape. Every character of a bold word after its first comes out as NUL (`F\x00\x00\x00\x00\x00 S\x00\x00\x00\x00\x00:` for `Filing Status:`) instead of stray whitespace. The extractor still strips whitespace, and also lets NUL stand in for any single character, which matches both forms. On real 2025 filings the optional line called "Sub Owner" above is labelled `Subholding Of:`; it lands in the silver `sub_owner` field. `Location:` and `Comments:` lines also occur and are in the dictionary.

The walk from the anchor is bounded by the anchor's own table row, and rows are delimited by vertical whitespace in the text layer (about 26pt between rows, at most about 21pt inside one), not by text. Text alone can't tell a wrapped label value (a multi-line `Comments:`) from the next row's asset line, so a text-only walk misattributed one to the other. Measured over 57 sampled filings (1,650 rows), the gap split every row correctly. A row split by a page break continues after the next page's column header with no transaction line of its own, and is joined back to the row above it.
